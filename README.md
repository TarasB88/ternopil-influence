# Ternopil Influence Dashboard

Вебдашборд епідеміологічної ситуації із захворюваності на грип, ГРВІ та COVID-19 у Тернопільській області.

## Можливості початкової версії

- Вибір доступного звітного періоду; останній період вибирається автоматично.
- Кнопка «Оновити з Google Sheets»: отримує опублікований CSV, зіставляє відомі назви колонок і перемикає дашборд на онлайн-дані лише якщо знаходить мінімально необхідні поля.
- Перемикач української та англійської мови (UKR/EN).
- Динамічне епідеміологічне зведення, KPI-картки та графіки.
- Окремі показники для дітей, школярів, госпіталізацій, COVID-19, ПЛР і стічних вод.
- Адаптивна верстка для комп'ютерів і мобільних пристроїв.
- Health endpoint: `/api/health`.

## Проміжний словник даних

Файл `public/data/data-dictionary.json` визначає цільову схему дашборду, типи полів, можливі українські назви колонок-синонімів, правила нормалізації та перевірки якості. Кандидати назв у `source_aliases` ще не підтверджені за реальним CSV. Перед активацією автоматичного мапінгу потрібно перевірити фактичні заголовки аркуша й зафіксувати відповідності; невідомі поля не відкидати мовчки.

## Джерело даних

Початкові показники інтерфейсу завантажуються з `public/data/weekly.json`. Кнопка «Оновити з Google Sheets» запитує `/api/source`, намагається зіставити заголовки з відомими назвами полів і використовує онлайн-дані лише коли знайдено записи з роком, тижнем і загальною кількістю випадків. Стан Worker — `/api/health`.

**Важливо:** фактичні заголовки CSV не були перевірені під час розробки. Тому автоматичне зіставлення навмисно консервативне: якщо поля не розпізнані, інтерфейс повідомляє про проблему й залишає поточні показники, не видаючи локальні дані за оновлені. Якщо це повідомлення з’являється, потрібно звірити заголовки CSV із `public/data/data-dictionary.json` і додати точні відповідності.

Після підтвердження заголовків слід протестувати всі зіставлені поля та якість даних на реальних рядках. Історичні значення не вигадуються.

## Локальний запуск

Потрібен Node.js LTS.

```bash
npm install
npm run dev
```

## Розгортання через Cloudflare

1. Відкрийте Cloudflare Dashboard → Workers & Pages.
2. Створіть Worker або імпортуйте цей GitHub-репозиторій через доступний Git integration workflow.
3. Для Git-based build задайте команду збірки/розгортання `npm run deploy`; якщо середовище очікує окремі поля, використайте `npm install` як install command.
4. Переконайтеся, що Worker використовує `wrangler.jsonc` з assets directory `./public`.
5. Після розгортання перевірте головну сторінку та `/api/health`.

> Примітка: прив'язка GitHub до Cloudflare, вибір облікового запису та авторизація виконуються у вашому Cloudflare Dashboard. Секрети й токени не зберігати в репозиторії.

## Наступні кроки

- Додавати кожен новий звітний тиждень у структуру даних.
- За потреби підключити контрольоване джерело даних (наприклад, Cloudflare D1 або захищене завантаження CSV/XLSX).
- Перевірити показники проти первинного офіційного звіту перед публікацією.


## Автоматична перевірка перед змінами

Команда `npm run check` перевіряє синтаксис Worker, структуру локального набору звітних періодів, словник даних і геометрію громад. GitHub Actions запускає цю перевірку для кожного push до `main` та pull request.

Перевірка формату не підтверджує епідеміологічну достовірність чисел. Початковий `weekly.json` містить один звітний період; перед офіційним використанням його показники необхідно звірити з первинним звітом. Автоматичне зіставлення заголовків Google Sheets залишається непідтвердженим, доки не перевірено фактичний CSV.


## Підключення нового джерела «Грип, ГРВІ, COVID-19 та вакцинація»

Новий формат очікує дві опубліковані CSV-адреси Google Sheets:
- `RESPIRATORY_CSV_URL` — аркуш `weekly_respiratory`;
- `VACCINATION_CSV_URL` — аркуш `weekly_vaccination`.

У Cloudflare Worker потрібно додати обидві змінні як Variables (не Secrets, якщо це лише публічні URL), де значенням є повна URL-адреса експорту потрібного аркуша у CSV. Після налаштування доступні проксі-ендпоїнти `/api/respiratory` і `/api/vaccination`. Якщо змінну не налаштовано, ендпоїнт повертає HTTP 503 із чітким статусом `not_configured`, а не маскує проблему під нульові дані.

Старий `/api/source` залишено тимчасово для сумісності під час міграції. Він усе ще читає попередню таблицю, тому не вважається підтвердженим джерелом нового дашборду. Новий spreadsheet ID або опубліковані CSV URL потрібно додати до Worker перед повною інтеграцією.
